# 第1回 解答

## 演習

- 講座に固有の質問（宿題の3レベル）へのモデルの回答（要約でよい）：
  `gemini-3.5-flash-lite` は「AIE2026（AIエンジニア育成講座などの2026年目標のプログラム）」と推測したうえで、一般的なAI講座の分類として「レベル1：基礎・初級 / レベル2：応用・中級 / レベル3：発展・上級」を説明した。「多くの場合はレベル1は必須、レベル2・3は挑戦枠」とも答え、最後に「シラバスや講師に確認してください」と付け加えた。
- 用語集の正しい意味と比べて気づいたこと：
  正しくは「基礎（講義内容の確認）・実装（自分でコードを書く）・発展（調査や試行）」の3段階で、**どれか1つに取り組めば完了**、原則として採点しない。モデルの答えは「3段階の難易度」という大枠だけは偶然近いが、名称も「レベル1は必須」という運用も誤り。講座を知らないのに「〜の可能性が極めて高い」と自信ありげに一般論を組み立てており、確認を促す一文があっても本文はもっともらしい誤情報になっていた。
- 表示できたトークン数（入力 / 出力）：21 / 579（`gemini-3.5-flash-lite`、上の質問）

## 宿題

- 取り組んだレベル：発展
- 使ったモデル：`gemini-3.5-flash-lite`（既定）、`gemini-3.5-flash`
- やったこと：
  - `app/ask.py` に `usage_metadata` から入力・出力（・思考）トークン数を表示する処理を追加した。
  - `scripts/benchmark_ask.py` を作成し、2モデル × 3質問（一般(短)：一文で答えさせる、一般(長)：「LoRAとは何ですか？」、講座固有：3レベル）について、応答時間（`time.perf_counter`）とトークン数（入力 / 出力 / 思考）を計測した。
  - 計測A：各3回、呼び出し間隔5秒（`uv run python -m scripts.benchmark_ask`）
  - 計測B：各5回、間隔0秒で連続呼び出し（`--interval 0 --repeat 5`）。計測Aの直後に実行した。
  - 生データは `lectures/01/benchmark.csv`（A）と `lectures/01/benchmark_burst.csv`（B）。
- 結果：

  |---|---|---|---|---|---|---|---|

  ※ 生成tok/s =（出力 + 思考）/ 応答時間

- 気づき・疑問：
  - **応答時間の差はほぼ「思考トークン」で説明できる。** flash-lite は思考トークン0だが、flash は答えが一文（出力約50）でも思考に約500トークン使っており、生成量の約9割が思考だった。そのため短い質問でも flash は flash-lite の4〜6倍遅い。最終的な出力量は両者で大差ない（長い質問で 580〜600 vs 660〜730）。
  - **短い応答は固定の待ち時間が支配的。** flash-lite の一般(短)は生成tok/s が約50で、長い応答（約200）の4分の1。約50トークンしか生成しないので、ネットワークや前処理などの固定コスト（推定0.7秒前後）が応答時間の大半を占めていると考えられる。
  - **入力トークンは質問文の長さで決まる。** 「一文で答えてください」を足した一般(短)（14）のほうが一般(長)（7）より多い。今回はどの質問も入力が少なく、コストや時間は出力・思考側で決まっていた。
  - **レート制限：** 計測Bでは flash-lite は15回連続（約33秒間）すべて成功したが、flash は8回成功した後、9回目以降の7回すべてが 429 で、約0.2秒で即座に失敗した。計測B内の flash の成功8回は約54秒間（1分あたり約9回）で、直前の計測Aを含めると約4分間で計17回呼んだところで制限に達した。flash-lite は呼び出し回数がより多くても429が出なかったので、flash のほうが無料枠の上限が厳しいと考えられる。
  - 1回の flash 呼び出しは思考を含め1,000〜2,000トークンを生成するため、回数（RPM）だけでなくトークン量の上限（TPM）に効いている可能性もある。今回のスクリプトは 429 のエラーメッセージを保存していないので、どちらの上限（分単位か日単位か）に当たったのかは区別できていない。メッセージを記録する、1分待って再実行して回復するか確かめる、が次の課題。
  - 実用上は、講座の演習のように何度も試す用途では、速くて制限にもかかりにくい flash-lite が向いている。flash を連続で使うなら、呼び出し間隔を空けるか、429 のときに待ってから再試行（指数バックオフ）を入れる必要がある。
  - 疑問：flash の思考量は `thinking_config` で抑えられるはず。思考を減らすと、応答時間と回答の質がどう変わるかを試したい。
- AI ツールの利用：計測スクリプトの作成と、結果の整理に Claude Code を使った。計測の実行と数値の確認は自分で行った。
